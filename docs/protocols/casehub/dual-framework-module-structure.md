When extracting a framework-neutral core from a CDI-coupled module, the module splits into three artifacts following the `module-core/module/module-spring` naming convention. CDI producer classes that instantiate core POJOs as CDI beans live in a `quarkus/` subpackage within the existing module (e.g. `io.casehub.platform.view.quarkus.ViewBeans`). Spring auto-configuration classes live in a separate `-spring` module (e.g. `casehub-platform-view-spring`) and are generated by the `spring-generator` Maven plugin from the Quarkus module's Jandex index. Config-property-backed beans that the generator cannot handle are manually wired in a separate `*ManualConfig` class within the `-spring` module. The existing module's Maven artifact name is preserved — zero consumer breakage.
